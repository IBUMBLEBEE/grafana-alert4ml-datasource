# Funnel → K-means 可实现计划

日期：2026-09-27。状态：实施中（P1–P5 已完成，P6 部分完成）。仓库基线：`a1e5cbb`。本文件合并算法替换方案及 Grafana 动态步长讨论，也是实施与验收的任务清单。未勾选任务仍待完成或仅完成了其中一部分。

## 目标与范围

用 Netdata 风格的逐序列 K-means 模型集替换 Funnel；新检测类型为 `kmeans`，界面显示 `K-means`。删除 Funnel 专属的统计 L1、季节画像、三态路由和未在 Grafana 路径启用的 L2 编排。独立的 Dynamics 与 Forecast 保留；旧的第四种检测引擎已从产品和代码中移除。

本提案以 Netdata 官方源码为算法参考；实现事实、文档差异和固定版本引用见 [研究记录](netdata-kmeans-research.md)。使用 Rust 实现，不将 C++/dlib 引入 Grafana 插件进程。输出兼容现有 Grafana Alerting，且增加可解释的距离分数与模型状态。

实现不会自动修改已存面板或告警，也不清理数据库；旧查询只提供显式迁移操作。不涉及已暂停的 Prometheus 规则推荐或自动创建能力。

## 已确定的设计决策

- 新检测类型为 `kmeans`，不沿用 Funnel 名称或旧统计参数。
- Grafana 可继续自动改变显示步长；算法使用独立配置的固定检测步长。先在检测网格评分，再为图表聚合。
- 训练与推理共用特征变换、检测网格和版本；改变检测步长必须重新训练。
- 第一版完成算法替换、模型持久化、图表和 Alerting 适配；节点级 NAR/事件不在首版范围内。
- 表中的默认值是可实施初值，不代表已通过精度调优；回放发现问题时记录调整及算法版本，不宣称逐点复刻 Netdata。

## 算法与默认配置

采用每序列独立模型集；不把不同单位、不同标签的序列放在一次聚类中。两个质心都表示训练期间学到的行为模式，不能把某个簇直接命名为“异常簇”。

参考源码固定为 Netdata `4464a9ed71c8a7351b540ce4ca207e1418faffea`（2026-09-26）。它与用户提供的说明图及官方分析文档有差异：

- 特征顺序是 `diff → smooth → lag`。`diff_n=1`，`lag_n=5` 产生变换后序列连续六个值；不是“差分值 + 平滑值 + 四个原始滞后值”。默认平滑宽度为 3，但实际采集步长超过 profile 步长时降为 1。[特征源码](https://github.com/netdata/netdata/blob/4464a9ed71c8a7351b540ce4ca207e1418faffea/src/ml/ml_features.cc)
- K-means 使用两个质心；评分距离是到两个质心欧氏距离的**平均值**，不是最近距离。训练阶段对相同距离函数求 min/max。[评分源码](https://github.com/netdata/netdata/blob/4464a9ed71c8a7351b540ce4ca207e1418faffea/src/ml/ml_kmeans.cc)
- `score = min(100, 100 × abs((d - d_min)/(d_max - d_min)))`。Netdata 的零距离范围直接返回 0；项目的退化处理见下一节，属于显式差异。
- 预测中 `score < 99` 会否决异常，因此有效模型全部达到 `>= 99` 才通过；18 是模型池上限，源码对当前已有模型判定，并不强制等满 18。Netdata 跳过 NaN 模型且无模型时返回非异常，本项目改为显式不可用状态。[预测源码](https://github.com/netdata/netdata/blob/4464a9ed71c8a7351b540ce4ca207e1418faffea/src/ml/ml.cc)

项目首版使用固定 `diff=1, smooth=3, lag=5`，按实际检测步长计算特征时间跨度（默认 60s 意味着平滑覆盖 3 分钟），属于配置适配而非宣称完全复刻 Netdata 的 profile 自动切换。窗口结束于当前点，只依赖当前及过去；按时间升序的六维顺序固定。`z_t=x_t-x_(t-1)`，`y_t=(z_t+z_(t-1)+z_(t-2))/3`，`v_t=[y_(t-5),…,y_t]`；需要 9 个连续原始样本。训练和推理使用相同变换。不开启额外特征标准化或 Hampel 清洗。

Rust 训练拟采用固定种子的 K-means++ 初始化和 Lloyd 迭代，最多 1000 次，空簇重新选择最远训练向量。Netdata 使用 dlib 初始化；初始化差异必须记录在模型版本并通过回放比较，不承诺质心逐位一致。建议每窗最多 1440 个训练向量；不足则使用全部，超过则在构造特征后确定性抽样。归一化范围基于实际用于训练的向量计算。最终模型集分数取各有效模型分数的最小值，因而与全体一致判定一致；同时输出有效模型数。

| 参数                | 提议初值                 | 说明                                                            |
| ------------------- | ------------------------ | --------------------------------------------------------------- |
| `clusters`          | 2，内部固定              | 不提供“异常簇”选择                                              |
| `trainWindowSecs`   | 21600（6h）              | 每个模型的训练范围                                              |
| `retrainEverySecs`  | 10800（3h）              | 按事件时间对齐的窗口间隔                                        |
| `maxModels`         | 18                       | 成熟模型集规模                                                  |
| `anomalyThreshold`  | 99，分数范围 0–100       | 不是概率、置信度或第 99 百分位                                  |
| `consensus`         | 所有有效模型一致         | 不引入多数票作为默认                                            |
| `detectIntervalMs`  | 新查询默认 60000，可配置 | 项目默认，并非 Netdata 的采集频率；不得小于上游实际支持的粒度   |
| 历史范围            | 默认 60h，另加特征上下文 | 57h 模型覆盖 + 最多 3h 网格对齐余量；不再套用原 Funnel 七天默认 |
| `minModelsForAlert` | 18                       | 项目提议：成熟之前可预览，但不产生“可靠正常”或告警结论          |

窗口 `[T-6h,T)`、`[T-9h,T-3h)`……`[T-57h,T-51h)` 覆盖 57 小时。实现默认请求 60 小时，以容纳查询开始时刻到上一 3 小时训练网格的对齐偏移，之后再增加 8 个特征上下文点。Netdata 实际是队列调度并可能合并重叠模型，因此 57h 是理想窗口布局；本项目明确采用固定事件时间布局以方便查询重放。

6h 在 60s 步长下只有 360 个原始点。因此不能照搬以秒级采集为前提的绝对最小训练样本数。项目默认在网格容量允许时要求每窗至少 120 个有效特征向量，并始终要求时间网格有效覆盖率至少 90%；对于 5m/15m 等完整窗口本身不足 120 点的受支持步长，有效最小值封顶为期望向量数的 90%（并至少为 2），避免模型永久停留在 WarmingUp。训练抽样必须发生在完整连续特征构造之后。

## 缺失、常量与特征上下文

1. 时间戳去重、排序并验证固定步长；相同时间戳存在不同数值时给出明确数据质量错误。
2. null/NaN/Inf 和缺失时间格不填成 0；跨缺口的特征无效，直到再次拥有足够连续上下文。首版不做插值。这是项目相对 Netdata 的显式适配。
3. 当前检测窗口开始之前额外取特征所需的原始点，保持首点可检测；这些上下文不能混同为待检测点。
4. 不足以产生两个不同质心的常量训练窗口使用明确的退化模型处理。若训练距离范围为零，匹配的特征分数为 0，明显不匹配为 100；数值容差、版本和测试固定。该策略是项目适配，不能标称与 Netdata 完全等价。
5. 差分特征会削弱绝对水平和持续阶跃的敏感度；不能承诺持续高值一定持续报警。保留 Dynamics 作为另一个独立选项，不把统计基线重新塞回新检测器。

## Grafana 动态步长：取数、检测、显示三层契约

### 步长与时间网格

| 名称                        | 来源                                       | 是否进入模型身份 |
| --------------------------- | ------------------------------------------ | ---------------- |
| `detectIntervalMs = Δ`      | 已保存的查询配置，缺省 60000，必须为正整数 | 是               |
| Grafana 请求的 `intervalMs` | 面板时间范围、宽度等影响的显示需求         | 否               |
| `displayIntervalMs = D`     | 后端由显示需求、输出点预算及 Δ 推导        | 否               |
| 告警评估周期                | Grafana Alerting 调度                      | 否，不替代 Δ     |

K-means 不再接受 `detectIntervalMs=0` 表示跟随面板自动步长；缺省补 60000，显式非正值报配置错误。旧查询迁移时若没有固定步长，填写该默认值并告知需要新模型。

检测时间网格锚定 Unix epoch：`t_n = n × Δ`。窗口和缓存区间统一用半开区间 `[from,to)`；向上游发请求时处理其包含端点的语义，返回后裁剪、去重。只评分已经结束的采样区间，实时未闭合点不作为稳定检测输入。首版时间抖动不自动吸附到网格；不满足契约的上游响应返回可诊断错误。

显示网格同样锚定 epoch。设目标范围长度为 R、有效输出点预算为 B（缺省 1500），取：

```text
D = Δ × ceil(max(Δ, requestedDisplayIntervalMs, R/B) / Δ)
```

因此 D 是 Δ 的整数倍且不小于 Δ。面板要求更细显示时也不插值伪造检测点。边缘显示桶按其实际与查询区间的交集计数。

### 查询计划与分片

新增 backend 内部 `DetectionQueryPlan`，包含 `detect_interval_ms`、`display_interval_ms`、`eval_range`、`history_range`、`context_range`、预期点数和预算。具体 `training_windows` 由拥有训练参数的 `rsod-kmeans` 按同一 epoch 锚点确定；backend 通过 60h history、3h 最坏对齐余量和 8 点上下文测试其覆盖范围。算法模块只接收固定网格数据，不读取显示步长。

1. 依据待评分时间范围推导全部所需模型窗口，合并重叠历史读取范围。默认特征需要 9 个原始点，因此每段特征开始前额外获取 8 个检测步长的上下文。
2. current 与 history 请求均使用 Δ。上游请求的点数上限由实际取数区间和 Δ 推导，不沿用面板输出点数预算；必要时拆分请求，所有分片使用同一全局网格。
3. 分片顺序处理并保留尾部 8 点，或在边界请求重叠上下文；重叠点只评分一次。训练先构造完整特征，再抽样，不通过降低查询精度节约训练成本。
4. 校验响应时间戳、缺失率及上游有效精度。响应只有零星缺口则标记无效；系统性降采样则报 `ResolutionMismatch`，不能当成一般缺失继续训练。
5. 缓存键包含查询语义、完整序列身份和 Δ；不同 D 可以复用训练数据与模型。仅缓存闭合区间；不会把面板宽度放进模型键。

上游 Adapter 必须设置真正控制 range query 精度的字段，不能假设只写通用 `intervalMs` 就足够。第一版验证 Prometheus 与现有集成测试使用的数据源；不支持固定精度的 Adapter 返回明确错误。检查模板变量路径：在构建内部检测请求时，让 `$__interval`/`$__interval_ms` 按 Δ 解析；`$__rate_interval` 由明确的抓取间隔配置和 Δ 推导。禁止让已经按显示步长展开的表达式进入训练请求；对无法可靠重建的表达式要求使用显式窗口。查询中显式写出的 `rate(x[5m])` 保留，表达式本身进入模型键。本项仅保持已有用户查询的执行语义，不生成或推荐 PromQL。

检查时间戳只能证明输出网格，不能证明上游保留了原始精度。若上游只剩 5m 降采样数据，即使可插值成 1m，也不能训练 1m 模型；使用 Adapter 的精度元数据或显式数据源配置验证。无法验证时在诊断信息标注精度未验证，不宣称恢复了原始信息。

首版资源初值：每次上游分片最多 10000 点、单请求所有序列与区间合计最多 1000000 个原始点、上游并发最多 4、训练 worker 最多 2；配置放在插件实例级，并遵循 Grafana 请求取消/超时。取数前估算，返回后按实际序列数再次检查。超预算返回 `BudgetExceeded`，附建议缩短范围或显式增加检测步长。不得静默提高 Δ、丢弃旧区间或返回部分结果却标为完整。

### 显示聚合与告警

检测结果先按 Δ 完整计算，再按 D 聚合。新增 backend 内部 `aggregate_detection_for_display`，不把聚合结果回送训练器。

| 输出     | 按显示桶聚合规则                                                                     |
| -------- | ------------------------------------------------------------------------------------ | --- | --- | ----------------------------------------------------------------------------- |
| 原始值   | 查询参数 `displayReducer: mean                                                       | min | max | last`，默认 mean，仅影响显示；明确它处理的是用户查询结果，不推断 counter 语义 |
| 异常标记 | 有任意有效异常为 1；无异常但有无效检测点为 null；全部应有点有效且正常才为 0          |
| 异常点   | 选择有效异常中分数最高者的真实原始值与真实时间戳；同分选最早点，不拿桶均值伪造异常点 |
| 分数     | 有效点中的最大分数，字段明确命名为区间最大分数；无有效点为 null                      |
| 覆盖率   | 有效检测点数 / 桶内应有检测点数，区分缺失、训练不足与正常                            |

异常点可以使用单独 frame，保留真实时间戳；图例说明大范围视图仅显示每桶代表异常点。DAR 仍是第二阶段的可选模式，公式为异常有效点数 / 有效检测点数；不能用聚合后的 0/1 再计算时间异常率。

`AlertSignal` 绕过显示聚合，直接返回 Δ 上的可空 0/1 和完整 labels，由 Grafana 表达式决定时间范围、归约及 `for`。评估周期可以与 Δ 不同；重复请求不会消费异常或改成 0。对窗口含部分 null 的情形，集成测试必须核对所选 Grafana reducer 的行为，不把“有一部分 null”误称为必然触发 NoData。

### 动态步长验收场景

- 同一固定时间段、Δ=60s，面板宽度改变或显示步长从 1m 改成 5m：内部逐点分数、标记与模型键相同，仅响应显示聚合不同。
- 面板从 1h 扩到 7d：重叠时间段使用相同历史窗口和种子时检测结果相同；请求点数不受旧 1500 点逻辑降精度影响。
- 五分钟桶内仅一个一分钟异常：显示标记为 1，保留该异常的原始值；若其余全有效，DAR 将为 20%。
- 用户将 Δ 从 60s 改为 300s：产生新模型键并重新训练，旧模型不误用。
- 上游返回 300s 数据而要求 Δ=60s：返回精度不匹配或明确的不可检测状态，不填零、不插值。
- 改变分片大小、缓存命中与否或同时打开两个不同宽度的面板，不改变同一点的检测结果。

## 时间语义与训练生命周期

本插件按 Grafana 查询触发，Netdata 在采集时持续检测。第一版采用查询驱动的训练与模型缓存，不添加后台采集服务。

- 首次查询若历史充足，可回填 18 个历史窗口模型；若不足，显示 `WarmingUp (m/18)`。可以展示已有模型的预览分数，但告警输出不得把未就绪当作 0。
- 评分点 `t` 只能使用训练结束时间不晚于 `t`、且不包含 `t` 的模型；按时间顺序推进模型窗口，禁止拿查询结束时的模型反算整个面板。
- 同一序列同时被面板和 Alerting 查询时，按模型键与窗口截止时间合并训练任务，使用有界工作池。CPU 训练/同步存储操作放入 blocking worker，避免堵塞异步请求执行器。
- 训练模型发布为不可变快照；失败不覆盖健康模型。新训练失败时，若仍有满足窗口新鲜度的完整模型集，可以继续使用并标注降级；过期或不足则返回不可用。
- 查询历史时间时，只加载满足截止时间的模型版本，必要时从相应历史重新训练。历史重建和实时模型快照分开，历史查询不得把实时状态回滚。
- 同样输入、参数、模型版本和随机种子必须得到相同结果。单纯重放历史不等于“当时已经产生的不可变异常记录”；要实现后者，需要单独持久化带模型版本的逐点判断，放到后续阶段。

推理成本约为 `O(M×k×d)`，成熟配置为 18×2×6 的距离计算；训练为迭代聚类，必须独立设置样本和迭代预算。不能直接把 Netdata 的 CPU/RAM 宣传值当作本插件性能目标。

## 模型与存储

新建 `rsod-kmeans` 模块，内部建议包含：`features`、`model`、`ensemble`、`config`、`storage` 和 `engine`。纯特征、训练、评分函数不认识 Grafana、网络和数据库；`engine` Adapter 满足现有 `Detector` Interface，组织配置与模型仓库访问。测试优先覆盖此接口和纯算法契约，不为每个内部函数制造独立抽象。

模型至少保存：格式版本、算法/预处理版本、采样步长、配置摘要、系列身份摘要、训练窗口起止、训练数据摘要、随机种子、质心、距离归一化范围及训练质量摘要。模型键使用新前缀 `kmeans:v1:`，避免读取 `funnel_profile:`。

训练预算、缓存大小和并发数按实例设置上限；查询步长或表达式变更产生新模型键。模型持久化复用 `rsod-storage`，但需要在 K-means 仓库层实现版本选择和原子发布，不能只覆盖一份无法追溯的最新 blob。数据库不可用时可明确降级为进程内缓存，响应携带持久化状态，不声称能跨重启恢复。

旧 Funnel blob 保持不可达且不再更新；不在插件启动时扫描删除用户模型。需要清理时另提供按前缀/版本筛选的显式迁移工具。

### 结果契约与就绪状态

在 `DetectionResult` 增加可选的 `scores`、`validity` 和模型诊断信息，旧检测器缺省为 None 并维持原输出；K-means 的每个向量长度必须与 timestamps 相同。`anomalies` 保持现有内部 0/1 存储，但 validity=false 时数值只是占位，所有 K-means 渲染/聚合路径必须读取 validity 并输出 null。模型级诊断不额外添加到 AlertSignal 的数值字段中，避免污染告警归约。

就绪状态：`WarmingUp`（模型不足）、`Ready`（完整且有效）、`Unavailable`（精度/质量/预算不满足）。每点同时标记数据有效性。必须区分“判为正常”和“没有判定”；可预览但未满足成熟门槛的分数不得转换成告警结论。

模型集合以 3h 网格窗口编号存储，评分 t 选定的 18 个截止时间可确定重建。首版不使用过期模型替代缺失的指定窗口：模型数不足就是 WarmingUp/Unavailable；这样面板回放不会因查询顺序改变投票集合。前文允许使用健康缓存，具体仅指这些指定窗口已存在的有效快照。

任务被取消时终止尚未开始的工作；已运行训练在迭代边界检查取消，不发布不完整模型。精度/配置不匹配返回 query error；输入缺失/暖机返回可空检测结果和状态。并发训练按模型键+窗口编号 single-flight，模型快照原子持久化。

## Grafana 输出与异常率

- `Visualization`：仅返回原始指标和稀疏异常点，不暴露 `AnomalyScore` 字段。当前窗口没有任何异常点时省略 `Anomaly` 列，避免图例留下空序列。0–100 分数保留在检测与显示聚合内部，用于阈值、全体共识及代表异常点选择。
- `AnomalyPoints`：仅输出有效且被判为异常的原始值。
- `AlertSignal`：每条有明确身份的序列输出一个可空的 0/1 数值字段，labels 保留。未就绪和无效点是 null/NoData，不是 0；全窗口无有效值时让 Grafana 的 NoData 策略处理。`render_alert_signal` 已根据 validity 将无效点渲染为 null。
- 连续异常在每次评估中仍返回 1，让 Grafana 的 `for`、恢复与通知去重工作。删除 Funnel 专属的 `latest_only`/`dedupe` 输出行为；也不照搬 Netdata 的 `SILENCED` 自动抑制状态，避免因抑制而误触发恢复。这是告警语义上的显式适配。
- DAR（按序列的时间异常率）可在第二阶段作为输出模式：`异常有效点数 / 有效点数 × 100%`；同时报告覆盖率，无有效点返回 NoData。
- NAR（同一时间的跨序列异常率）需要固定的 node 标签、查询指标集合和有效覆盖要求。第一版不自动加入；未来只能称为“所选序列集合的 NAR”，不能把部分 PromQL 查询结果称为整个节点的指标集合。

不修改上游 Prometheus/其他数据源的存储格式。Netdata 的内嵌 1-bit 存储与全节点事件处理属于它的采集/存储系统能力，不能在本插件中直接复制。
